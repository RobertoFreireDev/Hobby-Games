# CLAUDE.md — Building PICO-8 Games

**This repository is a template for creating PICO-8 games with Claude Code.** It contains no
game: there is no cart at the root, only the reference documentation — this file plus the
gated docs listed below. Whatever the user asks for is built from scratch under `games/<name>/`.

**Every game lives in its own folder.** A game's whole cart is `games/<name>/game.p8` — there
is no cart at the repo root, and no single "game in progress" slot. Multiple games can exist
side by side under `games/`, each in its own directory with its own `game.p8`.

**Starting a new game:** pick a short kebab-case `<name>` and create `games/<name>/game.p8` as
a bare cart:

```
pico-8 cartridge // http://www.pico-8.com
version 43
__lua__
-- game name
-- by author

__gfx__
__label__
__sfx__
__music__
```

The whole game lives in that file's `__lua__` section. There is no `game.lua` and no
`#include` — edit the cart file directly. Open the code with two comment lines (`-- game
name`, `-- by author`); they are drawn onto the cart label. Assets go into the same file's hex
sections, generated by a Node script rather than hand-typed. Verify with
`pico8.exe -x games/<name>/game.p8` after every meaningful change. If the game has a jump,
read `PICO8-PHYSICS.md` **before** designing any level. When the user has not specified a
genre, mechanic or art direction, ask — do not default to a platformer just because the
physics doc is present.

**A game's own working files live alongside its cart**, in `games/<name>/` — `labelgen.p8`,
any `*gen*.js` asset generators, and its design/plan notes. Shared tooling stays at the root
(`label-tool.js` and the reference `.md` files). `nextgames/` holds notes for games not
started yet.

**Finishing a game** is just exporting it: `pico8.exe games/<name>/game.p8 -export
"<name>.p8.png"` into `publish/` (or run `publish.bat` for every game at once). Nothing needs
to move — the cart already lives at its permanent home under `games/`.

**Editing a cart while PICO-8 has it open.** Code and assets live in the same file PICO-8
writes, so the two can fight. After an external edit, `load games/<name>/game.p8` in PICO-8
before touching anything; after editing in PICO-8, `save` before asking for more changes. A
PICO-8 `save` rewrites the entire file and will discard unsaved external edits.

Everything below is distilled from the official PICO-8 manual (v0.2.7): a hard constraint or
an API you can rely on.

## Limits
- Screen 128x128, fixed 16-colour palette. 30fps (`_update`) or 60fps (`_update60`).
- Code: max **8192 tokens**. A bracket pair or a string = 1 token; commas, `local`, `end`, `.`, comments are free.
- 256 sprites of 8x8 (sheet = 128x128px). Map 128x32 tiles (128x64 using shared memory).
- 64 SFX, 64 music patterns, 4 audio channels.
- Numbers are 16:16 fixed point: -32768 .. 32767.99999, smallest step ~0.00002.

## .p8 cartridge format (plain text)
```
pico-8 cartridge // http://www.pico-8.com
version 42
__lua__
-- code here
__gfx__    128 lines x 128 hex digits (1 digit = 1 pixel colour)
__gff__    sprite flags, hex
__map__    32 lines x 256 hex digits (2 digits = 1 tile index)
__sfx__
__music__
```
Omit unused sections. Identifiers must be lowercase in .p8/.lua files. `#include foo.lua` pulls in external code at boot, resolved **relative to the cart's directory** — this template does not use it; the code sits inline in `__lua__`.

`-->8` on its own line splits the code into editor tabs. Purely organisational, costs no tokens — use it to separate update / draw / data.

> **API details — read [api-reference.md](api-reference.md) ONLY if** you need the exact signature, argument defaults or return value of a PICO-8 function beyond the summaries below (e.g. what `clip` returns, `split`'s separator rules, argument order in `sspr`/`tline`, which `stat(n)` index to read). ## Program structure
```lua
function _init() end   -- once at startup
function _update() end -- 30fps logic (use _update60 instead for 60fps)
function _draw() end   -- once per visible frame
```
Without these callbacks code runs top-to-bottom and you must call `flip()` yourself.

## Lua dialect
- Lua 5.2 syntax, **no standard library** — no `math.`, `string.`, `table.`, `io.`.
- Tables are 1-based; `#t` for length; `t.key` == `t["key"]`.
- PICO-8 shorthand: `if (cond) x=1 y=2` on one line; `+= -= *= /= %= ..=`; `!=`; `\` integer division.
- Bitwise: `& | ^^ ~ << >> >>>` or `band bor bxor bnot shl shr lshr rotl rotr`.
- Also available: metatables (`setmetatable`), coroutines (`cocreate coresume costatus yield`), varargs `...`.

## Colours
0 black, 1 dark_blue, 2 dark_purple, 3 dark_green, 4 brown, 5 dark_gray, 6 light_gray, 7 white,
8 red, 9 orange, 10 yellow, 11 green, 12 blue, 13 indigo, 14 pink, 15 peach

## Graphics
- `cls([col])`, `camera([x,y])`, `clip(x,y,w,h)`, `color(col)`
- `pset(x,y,[col])`, `pget(x,y)`, `sget/sset(x,y,[col])`
- `line(x0,y0,x1,y1,[col])`, `rect/rectfill(x0,y0,x1,y1,[col])`, `rrect/rrectfill(x,y,w,h,r,[col])`
- `circ/circfill(x,y,r,[col])`, `oval/ovalfill(x0,y0,x1,y1,[col])`
- `spr(n,x,y,[w,h],[flip_x],[flip_y])` — colour 0 transparent by default
- `sspr(sx,sy,sw,sh,dx,dy,[dw,dh],[flip_x],[flip_y])` — stretched blit
- `pal(c0,c1,[p])` p=0 draw / 1 display / 2 secondary; `palt(c,[t])`; `fillp(pattern)`
- `print(str,[x,y],[col])` returns rightmost x. P8SCII escapes: `\f7` fg, `\#c` bg, `\^w` wide, `\^t` tall, `\^i` invert.
- Button glyphs `⬅️ ➡️ ⬆️ ⬇️ 🅾️ ❎` are the right way to write control prompts. Verified: each counts as **1 character** to `#`/`sub`, but draws **8px wide** (ASCII chars are 4px) — budget `#s*4` only for plain text. Safe to emit from a generator script as long as the file is UTF-8 without BOM.

## Map
- `map(tile_x,tile_y,[sx,sy],[tile_w,tile_h],[layers])` — `layers` is a sprite-flag bitmask
- `mget(x,y)` / `mset(x,y,val)`; `fget(n,[f])` / `fset(n,[f],val)` — 8 flags per sprite (0..7)
- `tline(x0,y0,x1,y1,mx,my,[mdx,mdy],[layers])` — textured line sampled from map tiles
- Sprite 0 means "empty" and is never drawn.

## Input
- `btn([b],[pl])` held; `btnp(b,[pl])` newly pressed (auto-repeats after 15 frames, then every 4).
- Buttons: 0 left, 1 right, 2 up, 3 down, 4 O, 5 X. Players 0..7.
- Call `btnp` from inside `_update`/`_update60`. Left+right at once is impossible on a real pad — don't design for it.
- Mouse/keyboard is devkit-only: `poke(0x5f2d,1)` then `stat(30..39)`. Keep it optional for shared carts.

## Audio
- `sfx(n,[channel],[offset],[length])` — channel -1 auto-pick, -2 stop; `sfx(-1)` stops everything.
- `music(n,[fade_len],[channel_mask])`; `music(-1)` stops.

## Math
`max min mid flr ceil abs sqrt sgn rnd srand atan2 cos sin`
- **`cos`/`sin` take 0..1 for a full turn, and `sin` is inverted** (screen-space y-down).
- `atan2(dx,dy)` returns 0..1. `sgn(0)` returns 1. Use `flr(rnd(n))` for a random integer.

## Tables
`add(t,v,[i])`, `del(t,v)` (by value), `deli(t,[i])` (by index), `count(t,[v])`, `all(t)`, `foreach(t,f)`, `pairs(t)`.
`for v in all(t) do ... end` is idiomatic, and deleting during `all()` is safe.

## System & persistence
- `cartdata("unique_id")` once, then `dset(0..63,val)` / `dget(0..63)` for saves.
- `peek/poke` (+`peek2/peek4/poke2/poke4`), `memcpy`, `memset`, `reload`, `cstore`.
- Memory map: gfx 0x0, shared gfx/map 0x1000, map 0x2000, flags 0x3000, sfx 0x3200, screen 0x6000.
- `t()`/`time()` seconds since start, `stat(1)` CPU load, `stat(7)` fps, `printh(str)` for host-console debugging.
- `menuitem(index,label,callback)` adds pause-menu entries (index 1..5).

## Gotchas
- The bottom half of the sprite sheet shares memory with the bottom half of the map — use one or the other.
- A counter incremented by 1 per frame overflows after ~18 minutes; wrap it or use `t()`.
- Arrays start at 1; `foreach` starts at `t[1]`, not `t[0]`.
- Watch the token counter: short locals, tables over many globals, and shared code paths all pay off. There is no runtime token stat — the count is only visible in the editor.
- Put the title on the first two lines (`-- game name`, `-- by author`) — they're drawn onto the cart label.
- **Don't shadow builtins.** Every API name is a plain global you can silently clobber. The easy ones to hit with a variable name: `t` (`t()` is the clock), `time`, `count`, `add`, `del`, `all`, `sub`, `run`, `stop`, `flip`, `max`, `min`, `mid`, `type`. Name your frame counter `tk`, not `t`.
- **Never put the solid flag on sprite 0.** `mget` returns `0` outside the map, so a solid sprite 0 turns everything beyond the level edge into wall.
- Overriding a global function (e.g. `btn`) further down the file works — Lua resolves globals at call time. That is what lets a test harness append fake input to the end of `__lua__`; it is also easy to do by accident.
