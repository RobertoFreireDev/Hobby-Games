# PICO-8 game template for Claude Code

A starting point for building PICO-8 games with Claude Code. The repo ships **no game** —
just the reference docs Claude needs to write a good one. Clone it, describe the game you
want, and build from scratch.

Every game lives in its own `games/<name>/game.p8`, all in the `__lua__` section. There is no
separate `.lua` file and no `#include`. Multiple games can exist side by side, each in its own
folder — there is no single cart at the repo root.

## Setup

- Install Node
- Install VS Code extensions: `pico8-theme`, `pico8-ls`, `pico8-vscode`
- Run git clone and copy content (`.git`, `README.md`, etc) to the `pico-8/carts` folder
- Open the folder in VS Code and start Claude Code — `CLAUDE.md` loads automatically
- Describe the game. Claude creates `games/<name>/game.p8` as a bare cart and writes the Lua
  and asset sections straight into it
- In PICO-8, run `load games/<name>/game.p8` to open it

> `pico8-ls` does not understand PICO-8's shorthand (`+=`, `!=`, `\`), so it will flag those
> lines as errors. They are valid PICO-8 and safe to ignore.

### Keeping PICO-8 and the editor in sync

Both Claude and the PICO-8 editor write the same file, so don't let them overlap:

- After Claude edits a cart, `load games/<name>/game.p8` in PICO-8 before doing anything else.
- After editing in PICO-8, `save` before asking Claude for more changes.
- A PICO-8 `save` rewrites the whole file — unsaved external edits are lost.

## Layout

| File | What it is |
|---|---|
| `games/<name>/game.p8` | A game's cart: your Lua in `__lua__`, plus the asset sections |
| `games/` | Every game, one folder each, including whatever is currently in progress |
| `publish/` | Exported `<name>.p8.png` cart images, ready to upload |
| `images/` | Cart label art as plain PNGs, one per game (generated) |
| `html/` | Web builds, one `<name>.zip` per game, ready for itch.io (generated) |
| `nextgames/` | Notes and pitches for games not started yet |
| `CLAUDE.md` | Hard constraints and the everyday API cheat-sheet — always loaded |
| `PICO8-PHYSICS.md` | Jump/gravity constants and the level geometry they allow |
| `PICO8-GAME-STRUCTURE.md` | How to organise the Lua of a cart |
| `PICO8-ASSETS.md` | Byte/nibble layout of every hex section |
| `PICO8-LABEL.md` | Cover art: the `__label__` pipeline and thumbnail legibility |
| `PICO8-TOOLING.md` | Running and testing carts on this machine |
| `api-reference.md` | Full signatures, defaults, return values |
| `memory-map.md` | Addresses for `peek`/`poke` work |
| `label-tool.js` | Splices a `labelgen.p8` dump into the cart (see `PICO8-LABEL.md`) |
| `publish.bat` | Publishes every game at once — see Publishing below |
| `publish-all.js` | The Node script `publish.bat` drives |
| `notes.txt` | Personal export/publish notes |

Each game's own working files live alongside its cart in `games/<name>/` — `labelgen.p8` (the
throwaway cart that draws the cover art), any `*gen*.js` asset generators, and its design
notes.

The docs are the point of the template. `CLAUDE.md` is loaded into every session and gates
the rest behind "read this one ONLY if the task needs it", so Claude pulls in the physics
tables or the hex layouts only when it is actually doing that kind of work.

## Running

```bash
# headless: runs the cart, printh goes to stdout, exits on extcmd("shutdown")
"/c/Program Files (x86)/PICO-8/pico8.exe" -x games/<name>/game.p8
```

Assets are best generated by script rather than hand-edited — see `PICO8-ASSETS.md`. Use
**Node**; Python is not installed on this machine.

## Starting a new game

1. Pick a short kebab-case `<name>` and create `games/<name>/game.p8` as a bare cart:

   ```
   pico-8 cartridge // http://www.pico-8.com
   version 43
   __lua__
   -- game name
   -- by author

   __gfx__
   __label__
   __sfx__
   __music__
   ```

2. Tell Claude what you want to build. The first two lines of the code are `-- game name`
   and `-- by author`; they become the cart label.
3. If it has a jump, point Claude at `PICO8-PHYSICS.md` **before** any level design; the
   constants decide the geometry, not the other way round.
4. Verify with `pico8.exe -x games/<name>/game.p8` after every meaningful change.

## Finishing a game

Nothing needs to move — the cart already lives at its permanent home under `games/<name>/`.
"Finishing" just means exporting it:

1. Export the cart image: `pico8.exe games/<name>/game.p8 -export "<name>.p8.png"` and move
   it into `publish/` (or run `publish.bat`, which does this for every game at once).
2. Leave the shared tooling at the root: `label-tool.js` and every `*.md` reference doc.

## Publishing

Run `publish.bat` from the repo root to do every game in one go. For each
`games/<name>/game.p8` it produces three things, all named after the game's folder:

| Output | What it is |
|---|---|
| `publish/<name>.p8.png` | The cart image, ready to upload to the BBS |
| `images/<name>.png` | Just the `__label__` art as a 128x128 PNG — no cartridge frame |
| `html/<name>.zip` | The web build: `index.html` + `index.js`, flat, drop straight on itch.io |

The web export has to be named `index.html` (PICO-8 names the `.js` after it), so the
script exports into a scratch folder and zips the two files from there.

Flags: `--scale 4` for bigger label PNGs, `--only stone,triad` for a subset,
`--no-export` / `--no-images` / `--no-html` to skip a step (the web builds are the slow
part). `PICO8=<path>` overrides where the executable lives.

**A cart with no `__label__` gets only the cart image.** PICO-8 flatly refuses an HTML
export from a cart that has never had a label captured ("please capture a label first"),
so the script reports those and moves on. See `PICO8-LABEL.md` to make one.

Exported cart images live in `publish/`. See `notes.txt`: `export <name>.p8.png` for the
cart image, `export <name>.html` for a web build (rename `game.html` to `index.html` and
zip it with the `.js` for itch.io).
